## 유지보수

`lib/`는 원본 관리 화면의 렌더링과 클라우드 API, `public/`은 기존 디자인·편집기, `db/schema.ts`와 `drizzle/`는 영구 저장소 스키마입니다. Java 프로젝트는 기존 로컬 실행용으로 유지합니다.

`scripts/import-local.py`는 원본 디자인과 화면 템플릿을 가져오는 도구입니다. 다시 실행하면 복사한 정적 파일을 덮어쓰므로 클라우드 전용 변경을 확인한 뒤 사용합니다. 예전 확인용으로 두던 `.sites-runtime/import/`의 H2 백업은 2026-10-21 지웠습니다(소스 저장소와 배포 파일에는 원래 없음).

로컬 검증은 `scripts/smoke-local.mjs`, `scripts/check-extra-local.mjs`로 실행합니다. 두 스크립트는 `127.0.0.1:5173`의 개발 DB에만 검증 데이터를 만듭니다. 원본 로컬 백오피스와 운영 사이트를 대상으로 실행하지 않습니다.

배포는 Sites 스킬의 source helper로 소스를 저장한 뒤 해당 커밋의 압축 파일을 게시합니다. Windows에서는 설치된 Git Bash가 PATH에 있어야 하고 GNU tar에 `TAR_OPTIONS=--force-local`이 필요합니다. 저장소 인증 정보와 운영 비밀 값은 파일에 기록하지 않습니다.

## 역할별 권한

최상위 관리자는 계정·권한과 영구 삭제를 포함한 전체 기능, 관리자는 게시물·사이트 페이지·미디어 정리·휴지통 이동/복원, 서포터즈는 본인 글 작성·수정과 업로드를 사용합니다. 전체 방문 통계는 세 역할 모두 볼 수 있습니다. 게시된 본인 글의 내용도 수정할 수 있으며 게시 상태 변경은 관리자 이상입니다.

요청한 계정의 최초 등록은 비공개 런타임 설정 `CMS_ACCOUNT_PROVISION`으로 한 번 처리하고 D1에 완료 표식을 남깁니다. 같은 설정으로 다시 배포해도 권한 변경·비활성화된 계정을 되살리지 않습니다. 개별 이메일과 등록 설정은 소스에 넣지 않습니다.

권한 검증: `node scripts/check-roles.mjs` (격리된 메모리 D1/R2, 서로 다른 테스트 계정). 로그인 수단과 관계없이 같은 역할 정책을 적용합니다.

## 자체 계정 로그인

비밀번호는 무작위 salt를 적용한 scrypt(N=16384, r=8, p=5) 해시로 별도 `auth_credentials` 컬렉션에 저장합니다. 브라우저에는 비밀번호나 해시를 반환하지 않습니다. 서버 저장 세션은 8시간 후 만료되며, HTTPS에서는 `__Host-` 접두사·Secure·HttpOnly·SameSite=Lax 쿠키를 사용합니다. 세션 원문은 DB에 저장하지 않습니다.

로그인에는 동일 출처 검사를 적용하고, CMS의 나머지 변경 요청에는 기존 CSRF 검사를 유지합니다. 계정별 15분간 10회, IP를 플랫폼에서 제공하는 경우 IP별 100회의 로그인을 제한합니다. 비밀번호 재설정은 해당 계정의 기존 세션을 모두 취소하고, 역할 변경·비활성화는 다음 요청부터 적용합니다. 공개 회원가입은 제공하지 않습니다.

`node scripts/check-password-auth.mjs`는 실제 workerd와 격리된 D1/R2에서 ChatGPT 헤더 없이 자체 로그인, 초기 비밀번호 변경, 재설정·로그아웃·만료, CSRF·출처·시도 제한 및 역할 검증을 진행합니다. 운영 계정의 비밀번호를 테스트용으로 설정하지 않습니다.
